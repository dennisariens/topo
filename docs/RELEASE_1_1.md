## Implemented

- Explicit mappings for all eleven chapter icons, including `islands → topo-island`, with a visible generic-pin fallback for missing symbols. Existing symbols and original Nino WebP bytes are retained. Tests require that none of the eleven supported chapters needs the fallback.
- Static and runtime pizza explanations consistently use eight, with runtime text referring to eight earned pizza points; reward economics and the replay ledger are unchanged.
- One primary Start/Continue hero action, a secondary six-question smart round, the highlighted current chapter and a compact next-chapter preview. Later locked stops and earlier completed lessons live in keyboard-accessible native disclosures. All eleven stops, 33 stage buttons, Gold and manual/due reviews remain available with their original gates.
- Mobile navigation fits all five modes into two rows, with a compact single-row counter strip and `aria-pressed` state. Nothing essential requires horizontal scrolling. The original illustration, palette and rounded route/card identity remain.
- Technical map explanation is inside native **Over de kaart** details/summary. It remains keyboard accessible, without a multi-line provenance block interrupting a lesson. No map geometry or touch tolerance changes.
- `scripts/nino-feedback.js` contains the selected **NOW** registry, embedded into the third inline script and checked byte-for-byte by lint. Common correct-answer variants rotate in memory only. No extra child data is saved. Tokens render through textContent.
- Copy covers first/return/resume, stage starts, correct/incorrect/skip, six-question and shorter final round results, chapter completion/next theme, new Gold versus Gold replay/miss, and reviews. Chosen-place feedback uses the actual graded pointing ID. Gold is never announced at a six-question pause. Pizza/trip messages require actual engine reward events; replay cannot claim a duplicate reward. Exam grading stays unchanged and gets no new assistance promises.
