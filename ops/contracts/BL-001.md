# Sprintcontract — BL-001 Branch-inventaris

**Doel (1 zin):** Een volledige, controleerbare inventaris van alle branches (lokaal en remote) met per branch de status ten opzichte van `main` en een voorstel keep/merge/archive/delete, zonder iets te verwijderen.
**Waarom nu (target/mijlpaal):** M0 (deadline vr 20 nov) vraagt branches van ~71 naar ≤ 10 (actief ≤ 5). Zonder inventaris kan Dennis geen akkoord geven op de opruiming (`GIT_RELEASE.md` §6) en blijft de regel "max 5 open taakbranches" overtreden.
**Bouwer:** Claude Code (Sonnet) · **Evaluator:** evaluator-subagent · **Max runs:** 1

## Scope
- Wel:
  - Alle refs onder `refs/heads` en `refs/remotes` inventariseren, ontdubbeld op naam (`origin/x` en `x` = één rij; kolom "Waar" = lokaal/remote/beide).
  - Per branch: laatste commit (datum, korte sha, auteur), `achter` en `voor` t.o.v. `main` via `git rev-list --left-right --count main...<branch>`, patch-equivalentie via `git cherry main <branch>` (vangt squash-merges).
  - Voorstel per branch met actie uit `keep | merge | archive | delete` en een reden van één zin, volgens de regels in `ops/GIT_RELEASE.md` §6.
  - Samenvatting: aantal per actie en het resultaat na uitvoering.
- Niet:
  - Niets verwijderen, hernoemen, taggen, pushen, mergen of rebasen. Geen `git fetch --prune`. Geen `git branch -d/-D`, `git push --delete`, `git tag`.
  - Geen inhoudelijke review van de code op branches; geen `index.html` openen.
  - De opruiming zelf uitvoeren (volgt pas na akkoord van Dennis, aparte taak).
- Toegestane git-commando's (alleen lezend): `git branch -a`, `git for-each-ref`, `git log`, `git rev-list --left-right --count main...<branch>`, `git cherry`, `git rev-parse`, `git merge-base`.
- Bestanden die gewijzigd mogen worden:
  - `ops/reports/branches.md` (nieuw)
  - `ops/STATE.md`, `ops/RUNLOG.md`, `ops/BACKLOG.md` (alleen statusregel BL-001), `ops/LEARNINGS.md` (optioneel, afsluiting)
- Bestanden die gelezen moeten worden (en verder niets):
  - `ops/contracts/BL-001.md` (dit contract)
  - `ops/GIT_RELEASE.md` §1 en §6
  - `ops/STATE.md` (tabel Actieve werkstromen)

## Stopcriterium
Klaar wanneer 1–11 PASS zijn. Niet doorgaan met "verbeteringen" buiten de scope (bijv. tags aanmaken, branches opruimen, integratieplan). Die gaan als `idee` naar de backlog.

## Risico en rollback
- Risico: verouderde remote-tracking refs geven een onjuist beeld. Mitigatie: rapportkop vermeldt dat de inventaris op lokale refs is gebaseerd; `git fetch origin` (zonder `--prune`) mag vooraf, niets anders.
- Risico: squash-merges lijken uniek werk (`Voor > 0`). Mitigatie: kolom `Cherry-uniek`; bij twijfel `archive` in plaats van `delete`.
- Rollback: alleen documentwijzigingen; `git revert` van de BL-001-commit volstaat. Er worden geen refs aangeraakt.
