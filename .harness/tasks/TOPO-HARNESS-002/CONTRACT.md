## Scope / acceptance

Dependency-free local Node controller with persistent, bounded transitions: INTAKE → PLAN → IMPLEMENT → VERIFY → REPAIR → INDEPENDENT_QA → PACKAGE → REVIEW_READY; VERIFY success bypasses REPAIR, repair returns to IMPLEMENT/VERIFY. Explicit BLOCKED and OWNER_REVIEW_NEEDED preserve the prior phase and reason. Only typed evidence can satisfy transition guards. Each advance invocation permits at most8 transitions; subprocess deadlines are fixed and in-flight work is never automatically retried. Fixed safe actions may execute; no arbitrary shell payloads or pretend external agent launches.
B. docs/brain/{README,current-state,product,design,skills,lessons,review-queue} documentation with a generated structured index. Existing project docs remain authoritative. Reconciliation consumes allowlisted verification fields and repository event metadata, records source SHA/hash and provenance, distinguishes approved decisions/proposals/verified implementation/unverified claims/history, and never silently promotes claims. No learner storage, names, backup payloads, credentials or arbitrary issue/comment bodies are ingestion inputs.
C. Versioned skill registry and deterministic applicability rules for standalone TOPO. Inspect Codex, Hermes and repository instructions; vendor pinned PR64 topo-ui-design provenance with an explicit current-mission compatibility overlay. Required SKILL.md access is checked before applicable work; selected/available/read/used are separate evidence states. Usage requires an action/evidence reference and cannot be inferred from selection. Missing required skill blocks relevant work. No React tooling.
D. Structured outcomes, defects, retry fingerprints, durations, measurable costs (unknown remains null) and human interventions. Evidence-backed proposals are generated for review. Implement one narrow evidence-backed improvement with regression tests on a separate branch; do not merge/promote it. Changes to gates/permissions/core policy require independent verification and owner approval. No safeguard self-disable or automatic policy promotion.
E. Real local pilot on a safe existing candidate: verify and provisionally package the unchanged PR71 offline HTML using V2, demonstrate interruption and process resumption, retain actual logs/screenshots/skill evidence/brain updates and exact-SHA handoff. Reach REVIEW_READY only with valid independent QA; otherwise accurately BLOCKED at INDEPENDENT_QA, with a clearly provisional review bundle. No simulated success counted as pilot evidence. Review bundles use a strict file allowlist, excluding all backup/storage JSON even when produced by a fresh browser test.

## Persistence / trust
Atomic task snapshots plus append-only sequenced events, single-writer lock, integrity checks and explicit interrupted-action recovery. Durable external service is NOT installed: local CLI is executable now; supervisor/queue/scheduler, authenticated Codex/Hermes adapters, protected approval identities and secret storage remain external controller responsibilities, documented with invocation/resumption protocol. Local operator can edit files; this is not an OS sandbox or cryptographic independent-QA identity service. Independent QA evidence must bind exact SHA/artifact hashes and a distinct reviewer; any subsequent commit invalidates QA until the reviewer responds to the new exact head, including evidence-only commits. Verification implementation digests may document a narrow evidence-only delta but never transfer independent approval; local supplied records are explicitly not authenticated Hermes approval without trusted controller provenance.
